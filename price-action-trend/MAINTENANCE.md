# IBM 調價趨勢維護說明

## 一、維護原則

最新版 `IBM_Power_Storage_Tape_調價趨勢指數_*.xlsx` 是唯一資料來源。網站不自行重算價格指數，只讀取 Excel 已計算並儲存的結果。

網站程式碼以 GitHub repository 內的 `price-action-trend` 為唯一來源。`X:\price-action-trend` 是內網發布目錄，不直接修改其中的 HTML、CSS 或 JavaScript。

每次建置會產生三個內容一致的版本：

1. X 槽內網版：明文 `data.js`，供公司內網使用。
2. GitHub Pages 版：`protected-data.json`，輸入密碼後在瀏覽器記憶體中解密。
3. 單檔離線版：HTML 內含程式、樣式及加密資料，業務可在無網路時使用。

## 二、目前計算規則

計算規則版本：`v2-conservative-floor`

1. 同一型號、同一日期、同一零件類別有多筆資料時，先計算該類別平均。
2. 有公告基準時，該數值視為公告下限。
3. 有零件類別明細時，採用漲幅為「公告下限」與「適用零件類別平均」兩者較高值。
4. 沒有零件明細時，直接採公告下限；兩者皆無則為 0%。
5. TWD 匯率獨立累乘：`當期綜合漲幅 = (1 + 採用漲幅) × (1 + TWD) - 1`。
6. 指數依生效日累乘：`調整後指數 = 調整前指數 × (1 + 當期綜合漲幅)`。

原廠來源檔可保留原始欄位名稱以維持資料對應；主 Excel 與網站統一顯示為「公告基準」，節點漲幅顯示為「公告下限」。

例如 FS7600 在 2026/7/1 的公告下限為 40%，零件類別平均約 30.10%，因此採用 40%，不能把公告基準一起平均後降至公告下限以下。

2026/7/1 另有台幣匯率 -0.3%，適用 Power、FlashSystem 與 Tape 相關 MTM；必須和同日產品漲幅分開保存，再以複利合併。

## 三、加入新的調價節點

1. 將新公告 Excel、PDF 放入 Price Action 資料目錄。
2. 在主 Excel 的公告基準明細工作表增加生效日、公告日、各產品公告下限、TWD、來源與備註。
3. 在 `零件漲價明細` 增加型號、MTM、類別、筆數、平均、最小值、最大值及判讀。
4. 在 `調價明細` 為每個網站系列增加同一生效日的資料列，保持各型號日期順序一致。
5. 延伸 `調整前指數`、`調整後指數` 公式，確認上一期 Q 欄連到下一期 P 欄。
6. 在 `指數總覽` 增加日期與漲價內容欄，並延伸每個系列的指數。
7. 在 `圖表資料` 增加日期列，連結到各型號的調整後指數。
8. 用桌面版 Excel 完成重算並儲存。建置工具讀取的是 Excel 儲存的公式結果。

所有網站系列在每個時間節點都必須有一筆 `調價明細`。沒有直接調整時也要保留資料列，採用漲幅填 0%，才能維持完整時間軸。

## 四、加入更早的歷史紀錄

如果找到比目前基準更早的公告：

1. 在第一個歷史調價日之前增加一個基準日期，指數設為 100。通常可用前一個月月初，或可合理代表調價前價格的日期。
2. 將歷史節點依生效日插入所有相關工作表，日期必須由早到晚排列。
3. 從新的最早基準重新累乘全部後續指數。不要只在圖表前方補一個顯示點。
4. `圖表資料` 第一列資料必須是新的最早基準；網站滑桿會自動把它設為「自動最早」。
5. 原本 2026/1/1 等節點仍可由滑桿選為 100，方便和既有簡報比較。

資料跨年度時不必修改網站程式。日期、年份標籤、滑桿節點、明細表與未來兩個月虛線都會依 Excel 自動延伸。

## 五、建置三個版本

在 repository 的 `price-action-trend` 目錄執行：

```powershell
.\tools\build-and-publish.ps1
```

工具會尋找使用者 OneDrive `Price Action` 目錄中最後修改的主 Excel。也可以明確指定檔案：

```powershell
.\tools\build-and-publish.ps1 -Workbook "完整的 Excel 路徑"
```

程序只要求輸入一次密碼，密碼不會寫入檔案。建置完成後會更新：

- `X:\price-action-trend`
- repository 內的 `protected-data.json`
- `X:\price-action-trend\offline\IBM_Power_Storage_Tape_調價趨勢_Offline.html`

程序不會自動執行 Git commit 或 push。

## 六、發布前檢查

1. 內網版、GitHub 版與離線版的最新日期一致。
2. 三個版本的各型號最新指數一致。
3. FS7600 等情況不會低於公告下限。
4. 密碼錯誤時，GitHub 與離線版都不能顯示資料。
5. 離線版在關閉網路後仍能開啟、切換型號、拖曳基準及匯出 PNG。
6. repository 中沒有 `data.js`、Excel、PDF 或其他明文價格資料。
7. 確認 `git diff` 後再 commit 與 push。

## 七、檔案角色

頁面主要呈現圖表與調價時間軸。公告來源、適用範圍、型號計算說明收在可展開區塊；若日後新增節點，應在主 Excel 的 `指數總覽` 第 2 列寫清楚該日主要變動，前兩行會直接顯示在時間軸卡片，後續行與來源檔案可展開查看。避免將工作表儲存格位置或內部處理備註當成面向業務的摘要。

圖表預設只標示最新節點，避免多條曲線互相遮擋。使用者可開啟「顯示各節點數值」，畫面與匯出的 PNG 都會顯示所有日期的指數。數值後的 `[1]`～`[9]` 對應下方調價時間軸的節點順序。

密碼畫面版本號由建置日期自動產生，格式為 `verYYYYMMDD`。曲線明細的「當期變動」大字取自 O 欄綜合漲幅；下方灰字固定顯示 N 欄採用漲幅的判定來源（公告基準、零件平均或產品漲幅），有匯率時一併列出 F 欄，方便核對複利結果。

| 檔案 | 用途 |
|---|---|
| `app.js` | 共用互動圖表、滑桿、明細與 PNG 匯出 |
| `styles.css` | 三個版本共用的商務淺色樣式 |
| `auth.js` | GitHub 與離線版的瀏覽器端解密 |
| `tools/generate-data.py` | 從 Excel 產生標準網站資料並做結構檢查 |
| `tools/protect-data.mjs` | AES-256-GCM 加密與相容性自我檢查 |
| `tools/build-offline.mjs` | 將所有內容包成單一離線 HTML |
| `tools/build-and-publish.ps1` | 一次建置三個版本 |

## 八、安全界線

GitHub Pages 上的密碼層是瀏覽器端加密，適合降低靜態檔案被直接讀取的風險，但不等同伺服器端帳號權限。不要將原始 Excel、PDF、明文 `data.js` 或密碼提交到公開 repository。高度敏感或需要存取稽核時，應改用公司內網登入或具備伺服器端驗證的主機。
